# 接口与系统集成

固定知识库与业务场景的独立问答入口，参见[知识库标准接口说明](知识库标准接口说明.md)。多通道意图查找参见[综合查找接口说明](综合查找接口说明.md)。新接口使用专属密钥；原应用检索与问答接口继续保留。

## 1. 调用边界

网页业务接口使用 HttpOnly 登录会话；写请求必须来自 `ALLOWED_ORIGINS` 配置的浏览器来源。服务端再次判断角色、知识库、涉密范围、文档状态和有效期。网页隐藏按钮不是授权依据。

外部应用通过“应用服务”创建专用只读令牌，只调用 `/api/service/search` 与 `/api/service/answer`。不要复用管理员浏览器 Cookie，也不要向客户端分发模型服务密钥。

令牌创建时选择知识库和有效期，秘密值只显示一次，服务器仅保存摘要。权限同时受令牌范围、令牌责任账号状态和当前知识库权限约束；撤销令牌或停用责任账号立即生效。

## 2. 应用检索与问答

以下示例中的 `XRAG_SERVICE_TOKEN` 应由调用应用的秘密配置提供。

```javascript
const origin = 'https://企业知识库域名';
const headers = { Authorization: `Bearer ${process.env.XRAG_SERVICE_TOKEN}` };
const query = new URLSearchParams({ q: '采购审批要求', baseId: '实际知识库ID' });
const result = await fetch(`${origin}/api/service/search?${query}`, { headers }).then(r => r.json());
const answer = await fetch(`${origin}/api/service/answer`, {
  method: 'POST',
  headers: { ...headers, 'Content-Type': 'application/json' },
  body: JSON.stringify({ question: '采购金额超过十万元需要什么审批？', baseId: '实际知识库ID' })
}).then(r => r.json());
```

检索返回 `{ query, results }`，结果带文档、知识库、页码、文本与排序信息。问答必须指定授权知识库，返回 `{ answer, mode, citations, warning?, usage? }`。

`mode=model` 表示实际模型归纳；`extractive` 表示原文摘录；`insufficient` 表示依据不足。集成界面必须保留该区分和引用，不要把摘录或无依据提示当作已经验证的模型回答。

应用问答调用会消耗配置模型的用量。接口有频率限制，调用方应设置超时与退避，不因网络超时无限重试。

## 3. OIDC 统一登录

设置 `OIDC_ISSUER`、`OIDC_CLIENT_ID`、需要时的 `OIDC_CLIENT_SECRET`、`PUBLIC_ORIGIN` 和可选 `OIDC_LABEL`。在身份平台注册精确回调地址：

```text
https://企业知识库域名/api/auth/sso/callback
```

系统使用授权码流程、PKCE S256、state、nonce，验证发行者、受众、签名和时效。只接受已验证邮箱，匹配企业知识库中事先创建且启用的同名账号；首次匹配后绑定发行者与 subject。不会自动创建管理员或依据外部任意角色字段提权。

例如身份平台返回已验证邮箱 `name@example.com`，应先在“组织与人员”创建账号 `name@example.com` 并按职责赋权。部门与文档权限仍在知识库侧控制。

自动测试使用隔离的本机身份提供方，已覆盖正确登录、错误签名/发行者/受众/nonce、未验证邮箱、停用账号等边界。正式环境还需用企业身份平台验证回调白名单、代理、TLS、成员离职与运维恢复。无配置时页面明确显示未接入，不会模拟统一登录。

## 4. Webhook 事件通知

在“应用服务”添加 HTTPS 公共接收地址，选择 `document.published`、`document.archived`、`document.upload` 或 `document.parse_failed`。签名密钥只在创建时显示一次，请写入接收系统的秘密配置。

请求正文示例：

```json
{
  "id": "实际事件ID",
  "event": "document.published",
  "occurredAt": "2026-09-07T00:00:00.000Z",
  "documentId": "实际文档ID"
}
```

正文不含文档内容、用户会话或模型密钥。请求头为 `X-XRAG-Timestamp`、`X-XRAG-Signature` 和 `X-XRAG-Event-ID`。签名算法为 `HMAC-SHA256(secret, timestamp + '.' + 原始JSON正文)`，头值形式为 `sha256=十六进制摘要`。

接收方应读取原始字节验证签名，用恒定时间比较，限定时间偏差（如 5 分钟），并按事件 ID 去重后才处理业务。响应 2xx 表示接收成功；失败按 1 分钟、2 分钟退避，总计最多 3 次尝试。地址不允许重定向，内网地址不会因为模型地址白名单而被放行。

通知采用至少一次投递：进程可能在外部接收成功后、记录成功前中断，因此接收方必须幂等。事件信封和游标持久化，重启可继续未完成投递；停用配置阻止新的投递并取消后续重试，已经发送的请求无法撤回。页面提供最近投递记录与测试入口。

## 5. 主要管理接口索引

| 功能 | 路径 |
| --- | --- |
| 就绪检查 | `GET /ready.json` |
| 知识库 | `GET/POST /api/bases` |
| 文档列表/上传 | `GET/POST /api/documents` |
| 文档详情/校对 | `GET/PATCH /api/documents/:id` |
| 文档动作 | `POST /api/documents/:id/actions` |
| 重建语义索引 | `POST /api/documents/:id/reindex` |
| 原件/安全预览 | `GET /api/documents/:id/file`、`GET /api/documents/:id/preview` |
| 运行保障/在线备份 | `GET /api/operations`、`POST /api/operations/backup` |
| 模型连接测试 | `POST /api/settings/model/test` |
| 评测用例/运行 | `/api/evaluations/cases`、`POST /api/evaluations/run` |
| 应用令牌/通知 | `/api/service-tokens`、`/api/webhooks` |
| 综合查找 | `GET /api/unified-search`、说明 `GET /api/unified-search/spec`（详见[综合查找接口说明](综合查找接口说明.md)） |

列表支持文档分页 `limit` 和 `offset`，默认 200、最多 500，正式页面每页 50。接口详情与数据字段以 `server/api.mjs`、`server/extensions.mjs` 和测试中的真实调用为准。


## 6. 结构化解析、复审及证据完整性

- 重新解析：`POST /api/documents/:id/reparse`，正文 `{revision,reason}`，返回 202 的 `{document,task}`。新文档进入后台队列，解析完成为 review；正式发布仍调用 actions。旧版本和原件保留。
- 治理办理：`POST /api/governance/actions`，包含 `documentId,revision,type,action,reason`。parse_warning 支持 acknowledge/reopen；review_due/no_review_date 使用 review，并提供未来的 nextReviewAt。复审可附 sourceKind/applicability/businessOwner 登记，不改变正文版本、状态或有效期。
- 文档修改与治理使用最新 revision。遇到 409 应重新读取并提示冲突，不能用旧快照覆盖别人的保存。服务端在完整收到请求后重新核验身份、权限、状态和版本，并在事务内提交。
- `GET /api/governance` 的 notes 为阅读说明，issues 为问题，acknowledged 告警保留结论；stats.total 只计算未办理问题。
- 表格片段的 table.schemaVersion 为 1，包含 tableId、headers、rows、rowNumbers、rowStart、rowEnd、totalRows。CSV 的 rowNumbers 为逻辑记录号，XLSX 为工作表行号。单片段 complete 只代表该片段是否已包含全表；聚合时还须核对连续行与字段一致性。
- 全表检索/问答提供 coverage.complete、totalRows、returnedRows 与 reason。预算不足或结构冲突不能报告全量统计。
- 模型引用保留正文原编号 citation，并标记 used。正文编号集合与模型声明必须一致；不能把未实际使用的检索候选当作答案依据。
- 评测用例支持 expectedTerms（最多 20 条必要文本）与 requireCompleteEvidence。每题结果保留 ruleSnapshot、sourceHit、textHit、completenessHit、missingTerms、coverageHit；这些规则检验不等于业务通用准确率。
