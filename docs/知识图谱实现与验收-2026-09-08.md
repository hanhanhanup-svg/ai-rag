# 知识图谱实现与验收

日期：2026年9月8日。代码、运行数据和浏览器证据均保存在当前项目。

## 实现范围

- 工作台：知识资产中的“知识图谱”，支持对象/问题查询、知识库与起点类型选择、1–3跳展开、节点和关系详情、关系列表、逐边原文定位及来源行高亮。
- 数据：从已解析表格明确字段提取线路、车站、设备、工单、故障、问题、规程和资料关系。知识库内明确编号跨文档对齐，站名按单位、线路或来源限定，未登记编号的问题保持来源范围。
- 治理：关系先进入候选；维护者查看来源后填写办理依据，确认或驳回，可一次办理最多50条，版本冲突整批回滚。
- 检索：关键词、本地BGE向量与已确认图关系融合。优先匹配问题目标的完整路径，预算不足时整条路径不纳入，不能展示缺少中间证据的链。
- 问答：真实模型收到图路径及原文；程序核对模型所用关系每一跳的引用。缺失时修复一次，仍不完整则回退原文；关系连通不能用来证明因果或制度效力。
- 运行：search_graph为只读工具，支持多步草稿；图检索记录在问答调用链。来源、权限或关系复核状态改变后，运行、历史会话、事件及草稿撤回过时依据。
- 一致性：检索等待向量期间更新文档或表格片段，不允许给旧内容盖新指纹；反向探索保留真实关系方向。

## 边界

当前是单节点、SQLite持久化的有证据关系图，使用有界遍历；没有将界面绘图等同于大规模图数据库。现有抽取基于明确表格字段，不声称任意正文的实体关系都已自动识别。知识库内编号应遵循同一编号管理范围；未登记的跨来源别名和同名对象不会自动融合。

查询最多3跳，每个视图最多200节点、400边；资料规模与并发性能需用企业实际语料验证。多条相似问题可能因缺少共同编号保留为不同节点，不能自行认定同一事件。

图谱关系仅代表已核对的来源关联，正式制度适用与现场作业仍须核验实际受控资料。

## 回退、撤回与备份

实际验收同时观察到：第一次模型答案成功后，身份范围关系更新使旧答案被撤回；另一次模型回答缺少完整引用，系统在修复未通过后返回原文摘录，未将其标为模型答案。相关记录为 previous-run-after-identity-update.json 和 model-citation-fallback-result.json。最终逐项引用问题在当前有效关系上成功返回model模式，三份来源与三跳路径均通过校验。
