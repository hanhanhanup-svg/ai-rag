# 知识库标准接口说明

把一个知识库与业务场景发布为固定的问答入口，业务系统每次只需提交问题，即可取得答案和原文依据。例如，维修系统可以接入“设备台账核对”接口，在当前工单旁展示相关资料。

这是知识问答服务。发布内容包括知识范围、场景、任务和可选业务对象；不会把智能助手的完整工具流程一并发布，也不会自动部署到公网。

## 1. 发布与使用

1. 管理员在“业务场景”中选择知识库和任务后发布，或进入“平台管理 → 知识库标准接口管理”创建。
2. 填写接口名称，选择一个普通知识库。场景和任务可同时留空，作为通用问答；指定场景时，任务须属于该场景。业务对象可不填。
3. 设置密钥有效期，默认 90 天，页面可选 30、90、180 或 365 天，管理接口支持 1–365 天。保存后取得调用地址和专属密钥。
4. 将密钥保存在接入系统的服务端秘密配置中，再由该系统提交问题。密钥只在创建或轮换成功时显示一次。

“机器学习”等系统知识库不能作为接口的发布目标。接口绑定的知识库、场景、任务和对象由管理员确定，调用方不能随请求改变。

## 2. 调用示例

调用地址由接口详情的 `endpoint` 字段提供，形式为：

`POST /api/service/knowledge/:id/answer`

请求头使用专属 Bearer 密钥，正文只接受 `question`，长度为 1–4000 字符。不要传入 `baseId`、`scenario`、`task`、`object` 或工具计划。

下面的环境变量由接入系统设置：`XRAG_ORIGIN` 为实际可访问的平台地址，`XRAG_KNOWLEDGE_ENDPOINT` 为接口详情中的相对调用地址，`XRAG_KNOWLEDGE_SECRET` 为专属密钥。

~~~javascript
const response = await fetch(
  new URL(process.env.XRAG_KNOWLEDGE_ENDPOINT, process.env.XRAG_ORIGIN),
  {
    method: 'POST',
    headers: {
      Authorization: 'Bearer ' + process.env.XRAG_KNOWLEDGE_SECRET,
      'Content-Type': 'application/json'
    },
    body: JSON.stringify({ question: '设备台账核对需要哪些资料？' })
  }
);
const result = await response.json();
if (!response.ok) throw new Error(result.error?.message || '知识接口调用失败');
// 同时展示答案、回答方式和原文引用。
console.log(result.answer, result.mode, result.citations);
~~~

响应包含 `answer`、`mode`、`citations`，也可能包含 `warning`、`usage` 或证据覆盖信息。调用界面应保留回答方式及引用，不能只展示一段答案文字。

| `mode` | 含义 |
| --- | --- |
| `model` | 已由配置的模型归纳，并通过当前引用校验 |
| `extractive` | 原文摘录，尚未经过模型归纳 |
| `insufficient` | 当前依据不足，不能给出确定结论 |

模型归纳不等于业务审批。涉及统计、完整清单或制度适用范围时，还应保留响应中的覆盖限制和原文核对入口。

## 3. 作用范围

- 每个接口只绑定一个知识库，只使用调用时可访问、已发布且仍有效的资料。停用接口、密钥到期或责任账号失效后不能继续调用。
- 场景、任务和对象用于组织本次问题，不赋予额外文档权限。
- 相关的已确认反馈经验可以辅助纠错，但其全部原始来源必须属于绑定知识库。其他库的经验、无原始来源的经验和已失效经验不会随接口输出。
- 纠错经验不作为原始表格记录或统计数值。答案事实仍须依据本次原文；生成期间来源、权限或学习结论失效时，旧内容不会作为有效结果提交。
- 调用实际生成模型会计入当前模型用量。接入系统应设置合理超时；遇到频率限制应退避，网络失败后不要无限重复请求。

## 4. 管理接口

以下操作使用管理员登录会话，适用平台现有浏览器来源及权限校验；专属 Bearer 密钥不能管理接口。

| 操作 | 路径与请求 |
| --- | --- |
| 查看列表 | `GET /api/knowledge-interfaces` |
| 创建 | `POST /api/knowledge-interfaces`，正文 `{name, baseId, scenario, task, object?, days?}`，返回 `{interface, secret}` |
| 启用或停用 | `PATCH /api/knowledge-interfaces/:id`，正文 `{expectedRevision, active}` |
| 轮换密钥 | `POST /api/knowledge-interfaces/:id/rotate-secret`，正文 `{expectedRevision, days?}` |
| 获取接口定义 | `GET /api/knowledge-interfaces/:id/openapi` |

`interface` 包含编号、名称、绑定知识库与场景、业务对象、启用状态、有效期、调用地址、调用次数、最近调用时间及 `revision`。管理更新时使用最新 `revision` 作为 `expectedRevision`；遇到版本冲突应刷新后重新操作。

轮换后旧密钥立即失效。先准备更新接入系统的秘密配置，生成新密钥后及时替换。服务器只保存密钥摘要，不能找回原秘密值；遗失时请轮换。接口不再使用时直接停用。

## 5. 常见处理与兼容性

| HTTP 状态 | 处理方式 |
| --- | --- |
| 400 | 核对问题长度、字段及场景任务组合；调用正文仅保留 `question` |
| 401 | 核对接口专属密钥、有效期及启用状态 |
| 403 | 请管理员检查绑定知识库、责任账号和当前资料权限 |
| 409 | 管理操作读取最新 `revision` 后重试；来源变化时重新提问 |
| 429 | 降低调用频率，退避后重试 |

原有 `/api/service/search` 与 `/api/service/answer` 继续保留，仍使用原“应用服务”令牌。标准知识接口使用独立密钥，两类密钥不能互换。已有集成无需为了使用原接口而迁移。

实际字段以接口提供的 OpenAPI 定义为准。平台对外可达地址、反向代理和 HTTPS 由运行环境配置；在本地创建接口不代表已经获得公网访问地址。
