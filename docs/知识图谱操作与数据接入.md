# 知识图谱操作与数据接入

本说明对应当前企业知识库的实际实现。知识图谱从资料中的明确表格字段建立关联，经复核后用于浏览和检索；每条关系保留文档、版本、证据片段和来源行号。

## 1. 从哪里使用

- **知识图谱**：打开 `/graph`，查看线路、车站、设备、工单、故障、问题、规程和资料节点，按知识库、起点类型、状态筛选，并展开关联路径。
- **文档详情 → 证据与关系复核 → 实体与关系**：针对一份资料提取候选，查看来源并确认或驳回。
- **智能检索、智能问答**：已确认且来源有效的图谱关系会参加现有关键词、语义检索。结果展示关联路径与原文引用。

例如输入 `SYN-EQ-005 关联规程`，选择三跳，可以寻找“设备 → 工单 → 问题 → 规程”路径。编号仅作界面操作示例，实际有无结果取决于当前已发布、已复核的资料。合成示例必须继续标明“合成示例”，不能当作真实维修或正式制度。

**起点类型**筛选的是开始查找的节点类型。输入设备编号时应选择“全部”或“设备”；选择“规程”表示从规程节点出发，不表示只保留结果中的规程节点。路径中的中间对象会保留，便于解释关联依据。

## 2. 支持哪些数据字段

资料应先完成解析，得到带表头、完整记录和来源行号的结构化表格。可以使用 CSV、XLSX 或其他已解析为原生表格的资料；图片、扫描表格如被标记为需要结构复核，应先确认结构，再抽取关系。

表头前后空格会忽略，英文表头不区分大小写。以下是当前识别规则，未登记的近义词不会被模型擅自映射。

| 对象或条件 | 当前支持的表头 |
| --- | --- |
| 设备编号 | 设备编号、设备编码、设备ID、设备标识；资产编号/编码/ID/标识；前面可加“关联”或“相关”；`asset_id`、`device_id` |
| 设备名称 | 设备名称、资产名称、`asset_name`、`device_name` |
| 车站名称 | 车站、站点、站名；前面可加“示例”或“所属”；`station_name` |
| 车站编号 | 车站编号、车站编码、`station_id` |
| 线路名称 | 线路、线路名称；前面可加“示例”或“所属”；`line_name` |
| 线路编号 | 线路编号、线路编码、`line_id` |
| 所属单位 | 所属单位、运营单位、运营公司、`organization` |
| 工单编号 | 工单编号、工单编码、工单ID、工单号、`work_order_id` |
| 故障编号 | 故障编号、故障编码、故障ID、`fault_id` |
| 故障描述 | 故障现象、故障描述、故障名称、`fault_name` |
| 问题编号 | 问题编号、问题编码、问题ID、`issue_id` |
| 问题描述 | 问题摘要、问题描述、问题名称、`issue_name` |
| 规程编号 | 规程编号、规程编码、制度编号、标准编号、`procedure_id` |
| 规程名称 | 规程名称、制度名称、标准名称、`procedure_name` |
| 资料编号 | 资料编号、关联资料编号、文档编号、`document_id` |
| 资料名称 | 资料名称、关联资料名称、文档名称、`document_name` |

“问题分类”可作为原文内容检索，但不能单独生成问题实体。“规程要求”等其他列仍保留在原文中，可为答案提供具体要求，不能仅凭规程名称推定要求内容。

### 一行表格如何生成关系

只有同一来源行存在相应字段时才生成候选：

| 来源字段 | 生成的关系 |
| --- | --- |
| 设备编号 + 车站 | 设备 → 位于车站 |
| 车站 + 线路 | 车站 → 属于线路 |
| 设备编号 + 工单编号 | 设备 → 关联工单 |
| 工单编号 + 故障/问题；没有工单时使用该行设备编号 | 工单或设备 → 关联故障/问题 |
| 规程 + 故障/问题/工单/设备 | 按故障、问题、工单、设备的顺序，选择该行存在的对象 → 依据规程 |
| 资料编号 + 规程/工单/设备 | 按规程、工单、设备的顺序，选择该行存在的对象 → 关联资料 |

不要求每张表都有设备列。例如一张表包含“工单编号、问题编号”，另一张表包含“问题编号、规程编号、规程名称、规程要求”，可以通过明确的问题编号接续已有关系。

设备只有名称、没有编号时，不据此自动建立设备关系。故障与问题分开保存；“资料目录待统一”等问题不会被改称为实际设备故障。

## 3. 跨资料对齐和同名对象

- **设备、工单、问题、故障、规程、资料的明确编号**：以“知识库 + 对象类型 + 规范化编号”为身份。同一知识库的两份资料可以连接相同编号；不同知识库、不同对象类型不会自动合并。规范化包括字符宽度、大小写和连续空白。
- **编号管理约定**：同一知识库内，每类对象的编号应唯一。如果多个业务系统使用相同编号表示不同对象，应先使用不同知识库或在接入映射时加入业务系统前缀；本功能不会推断编号冲突的真实含义。
- **线路**：有所属单位时以单位限定线路；没有单位时仅在当前知识库范围内对齐。
- **车站**：有线路时以线路限定站点。同名车站在不同线路上保持不同节点；换乘站也不会仅凭同名自动融合。缺线路时以资料来源族或连接器以及所属单位限定，不与其他来源的同名站点直接合并。
- **没有编号的故障或问题描述**：按工单或具体来源行限定。没有编号的规程名称按来源限定。

节点显示编号及作用域，便于人工辨识。目前没有全局同名融合、人工别名合并或企业主数据映射管理界面。

## 4. 推荐操作顺序

1. **接入并校核资料**：保留原文件，核对表头、来源行号和内容。扫描表格先完成结构复核。
2. **提取候选**：在知识图谱中选择知识库提取，或进入文档详情提取。重复执行相同来源的抽取不会覆盖已有复核结论。
3. **复核关系**：打开候选的原文，逐行核对对象、编号、关系及适用范围，填写依据后确认或驳回。批量复核仍须核对每条来源，不能把生成候选等同于事实审核通过。
4. **发布并检索**：默认图谱和问答只使用已确认、来源已发布且当前有效的关系。待审核文档的关系即使已确认，也不会进入普通检索。
5. **变更后重新核查**：文档内容、版本、权限、发布状态、适用范围或来源信息变化，会使旧关系失效或退出检索。根据当前来源重新抽取和复核；旧结论保留用于追溯。

来源撤权、过期、下架，或关系被驳回后，后续检索不再使用该关系。历史问答、工具结果和事件读取也会重新检查来源与关系状态，不能继续展示已撤回的旧依据。已经展示在浏览器中的内容应刷新后查看当前状态。

## 5. 检索行为和解释边界

检索先识别问题中的明确编号；没有编号匹配时，使用实体名称匹配。编号按完整边界匹配，`DEV-01` 不匹配 `DEV-010`。从匹配节点沿已确认关系展开一至三跳，遍历可以沿关系的两个方向查找，但保存的关系方向不变。

问题涉及规程、问题、故障、工单、车站、线路或资料时，相关目标路径优先。页面和问答按完整路径保留证据；若预算不足以容纳一条路径的全部来源，不把这条路径作为完整证据返回。未匹配到实体时，不凭相似主题编造关系。

关系连通只表示来源中登记的关联，**不等于因果、制度适用性、实际故障或已完成处置**。例如“设备 → 工单 → 问题 → 规程”可以帮助找到对应资料，但是否适用于当前作业仍须核对原文、单位、时间和业务条件。没有具体规程正文时，不能仅凭关联索引生成操作要求。

当前抽取面向明确表格字段，不包含任意正文的通用实体关系自动抽取、跨库全局别名融合、全图社区总结或不限跳数的图分析。

## 6. 接口与规模限制

接口沿用当前平台的身份、权限和来源校验。项目本地使用方式不要求另设账号密码。

### 查看图谱

`GET /api/graph?baseId=&query=&entityId=&hops=3&type=&status=confirmed`

- `baseId`：知识库范围；为空时取当前身份可访问范围。
- `query`：对象编号或自然语言关联问题。
- `entityId`：从指定节点展开，优先于文字识别起点。
- `hops`：1–3，默认 2。
- `type`：起点类型，支持 `asset`、`station`、`line`、`work_order`、`fault`、`issue`、`procedure`、`document`。
- `status`：`confirmed`、`candidate`、`rejected`、`stale`、`all`。普通读者仍只能看到有权使用的已确认有效关系。

返回 `nodes`、`edges`、`paths`、`stats`、`limits` 和 `canManage`。每条边和路径携带来源信息；`limits.truncated` 表示达到本次范围或展示限制，应缩小查询。

### 提取候选

`POST /api/graph/extract`

```json
{"baseId":"知识库实际编号","documentIds":["资料实际编号"]}
```

`documentIds` 可省略，此时处理范围内可编辑且已解析的待审核/已发布资料。指定资料时，任何不存在、范围不符或无权编辑的资料都会使本次操作失败，避免只成功一部分却被误认为完成。

### 批量复核

`POST /api/graph/relations/review`

```json
{
  "ids":[{"id":"关系实际编号","revision":1}],
  "action":"confirm",
  "reason":"已逐项核对原表编号、关系和来源行"
}
```

`action` 为 `confirm` 或 `reject`。`revision` 必须使用当前关系修订号；整批事务执行，任一关系已变化或无权处理时整批失败，刷新后重试。

| 范围 | 当前上限 |
| --- | --- |
| 单次抽取 | 100 份资料，合计 10000 行 |
| 单次批量复核 | 50 条关系 |
| 展开深度 | 1–3 跳 |
| 页面图谱 | 200 个节点、400 条边、100 条路径 |
| 问答图谱识别起点 | 最多 12 个匹配节点 |
| 图谱只读工具证据预算 | 最多 12 个来源片段；最终问答还受统一上下文预算限制 |

上限是单次操作或返回预算，不代表整个知识库只能保存这些对象。达到限制时应按知识库、明确对象和问题范围分批查询。
