## 浏览器与实际模型验收

通过 Microsoft Edge / Playwright，在 1440×900 桌面和 390×844 手机视口执行真实操作。17 张截图均已实际查看，手机页面无水平溢出，控制台错误 0、警告 0。重启后本地混合检索与索引重建、修复后中文文案、真实平均响应耗时均已复验。详细记录见 [浏览器验收记录](浏览器验收记录.md)。

真实链路为：初始化账号 → 上传采购制度 DOCX → 两页解析 → 校对摘要/标签 → 审核发布 → 搜索 → DeepSeek 问答 → 第 2 页引用定位 → 原件下载哈希核对 → 历史会话 → 提交反馈 → 创建备份 → 运行检索评测。

使用的是项目自建样本文档。实际回答包含“超过十万元应履行审批程序”和“归档资料保存五年”，分别有对应页引用。该证据证明实际模型、检索与引用链路连通，不用于声称企业全部问题的准确率。

本次重启后的 `/ready.json` 返回数据库与原件可读写、写入锁持有、队列就绪。正式页面与开发页面均返回 HTTP 200。

## 交付内容与使用步骤

交付目录包含前端、后台、完整构建、依赖锁文件、公开中文模型、测试夹具、部署配置和中文文档。运行 `scripts/package.ps1` 生成包含逐文件 SHA-256 清单的 UTF-8 ZIP，并重新读取每个归档条目核验；实际配置、用户数据、测试凭据、依赖安装目录均排除。

1. 当前电脑直接打开项目页面，创建企业管理员。
2. 按实际部门建立人员与库权限，再上传真实资料并审核。
3. 在“平台设置”核实模型状态，在“质量评测”建立本企业的标准问题。
4. 迁移服务器时按 [部署与运维手册](部署与运维手册.md) 安装依赖、安全配置密钥、验证公开模型并构建启动。
5. 上线前配置目标域名、HTTPS、备份介质、企业 SSO 与应用接收方，并执行对应环境验收。

## 尚需目标企业环境完成的事项

- 未连接实际企业身份提供方、事件接收系统或企业业务应用；相关实现通过本机协议和权限测试，外部连通须用企业配置验证。
- 当前机器没有 Docker 引擎，提供的镜像与 Compose 配置尚未在容器引擎实测。
- 未进行真实企业全量语料质量评估、大规模并发压测或高可用集群建设。检索采用进程内计算，部署范围为单节点。
- Office 复杂版式、嵌图与图表不是完整视觉还原。OCR 结果和关键业务条款须经知识责任人校对。
- 备份恢复已在独立目录实测；跨故障域保存、保留周期、磁盘告警与定期恢复演练由正式部署运维落地。

这些事项是明确的部署和规模边界，不能用已通过的本机验收替代。
