# 问答运行与追踪配置说明

版本日期：2026-09-08。适用范围为本项目当前 Node.js 24 / SQLite 单节点实现。本文根据实际接口与代码编写；正式模型、部署环境及浏览器验收结果应以当次验收记录为准。

## 1. 已实现能力与使用边界

连续问答每轮重新检查用户、知识库、文档权限、发布状态和来源版本。默认使用最近 6 个已完成轮次；较早内容保留有出处的用户条件摘要，并按长度裁剪。历史回答仅用于理解话题，不作为新事实依据。资料撤回或版本变化后，相关历史内容、运行结果和回放证据会重新检查并隐藏失效内容。前文有多个对象时，运行等待用户明确对象；前文依据已失效时，要求重新明确主题。

服务器真实读取模型 SSE 数据，先发送运行及步骤进度，再发送通过引用和结构校验的完整答案。当前并不逐字展示原始模型输出，也不保存模型内部推理过程。前端断开事件连接不会自动取消后台运行，需要调用取消接口。

来源不充分、完整编号不存在、全表覆盖不完整时，返回依据不足。生成模型未配置或未通过验证时，可以返回明确标注的原文摘录。有待复核冲突时并列提供相关原文，不替用户确定统一制度效力。只有人工确认等价的资料才合并重复候选占位。

媒体来源的 parseCoverage 为 partial，或画面覆盖为 sampled / partial 时，整段、全部、完整画面等问题不得被当作完整来源回答。普通片段问答会携带来源覆盖限制。复杂表格的结构未确认时，不进入完整统计。

引用检查只核对正文编号、实际引用集合及部分明显缺少出处的结论；业务输出检查只验证声明字段、类型、必填项及选项。两者均不代表全面事实核验。

## 2. 运行接口

下列接口沿用平台当前身份与权限机制。写请求需要通过既有 Origin 检查，服务端在读完请求正文后再次核验身份。运行、结果、事件和本地草稿仅向所属用户开放。

| 方法与路径 | 用途 |
| --- | --- |
| POST /api/chat | 保留同步 JSON 问答；同一会话的并发请求按序处理 |
| POST /api/chat/runs | 创建持久运行，返回 202 和 run |
| GET /api/chat/runs?conversationId=… | 当前用户的运行列表，最多 100 条 |
| GET /api/chat/runs/:id | 当前运行、步骤与可访问的结果 |
| GET /api/chat/runs/:id/events?after=N | 从事件序号 N 之后回放 SSE |
| POST /api/chat/runs/:id/cancel | 请求取消，先持久化 cancel_requested |
| POST /api/chat/runs/:id/inputs | 补充条件并恢复 waiting_input |
| POST /api/chat/runs/:id/retry | 明确重试失败、部分完成、取消或中断的运行 |
| GET /api/intelligence/capabilities | 实际工具、模型状态和固定运行限制 |
| GET /api/report-drafts/:id | 查看有有效来源的本地报告草稿 |

创建请求示例（编号由调用方实际取得，不能照抄占位值）：

    {
      "question": "统计本月设备费用，并列明缺失金额",
      "baseId": "实际知识库编号",
      "clientRequestId": "本次唯一请求编号"
    }

继续已有会话需提供 conversationId 和最新 conversationRevision。可选 scenarioVersionId 指向已发布模板，inputs 提供业务字段。服务端也支持受控 plan，用于逐步执行实际工具；不能通过该字段执行任意代码、SQL、shell 或网址请求。

同一 clientRequestId 和相同参数重复提交会返回原运行；改变参数但复用同一编号会返回 409。重复请求应保留原始参数及原始 revision，不要把它当作新请求重新拼装。新 run 接口在同一会话已有未结束运行时返回 409。

补充输入格式为 { revision, inputRequestId, inputs }；重试格式为 { revision, clientRequestId }。输入恢复保持原运行编号并增加 attempt。取消请求可附 revision。revision 冲突时应先读取最新运行，再由用户决定下一步。

SSE 支持 after 参数，也支持 Last-Event-ID 中的序号。事件包括 run.started、step.started、step.completed、evidence.ready、run.waiting_input、answer.segment、answer.final、run.succeeded、run.cancel_requested、run.cancelled、run.failed、run.partial、run.interrupted、evidence.withdrawn。事件号持久递增；已失效的历史事件内容会改为撤回提示。

## 3. 状态、恢复及预算

| 状态 | 含义与后续动作 |
| --- | --- |
| queued | 已持久化，等待调度 |
| running | 正在检索、执行工具或生成 |
| waiting_input | 等待必要业务字段或对象澄清，暂停活动计时 |
| cancel_requested | 取消意图已保存，正在停止执行 |
| succeeded | 本轮处理已结束；仍应查看答案 mode，可能是依据不足或原文摘录 |
| partial | 部分工具结果或显示范围未完成，不能视为全部办理成功 |
| failed | 执行失败，可按错误类别处理后明确重试 |
| cancelled | 取消已完成，或等待输入到期 |
| interrupted | 服务停止或重启时运行未完成，可明确重试 |

当前固定限制：每次运行最多 6 个工具步骤、90 秒活动时间；等待输入最多 30 分钟。等待期间不占用模型连接或数据库事务。终态释放会话占用。上述限制目前是代码内约束，没有单独的环境变量开关。

重启时，尚未执行的 queued 任务可恢复调度；执行中的任务标记 interrupted，取消中的任务标记 cancelled。已经原子提交答案、但来不及写入运行终态的任务会恢复为成功，不重复生成答案。

明确重试可以复用参数、依赖结果与来源指纹均未变化的已完成表格计算或条款对照步骤；来源更新后重新执行。搜索仍重新检索。本地草稿使用稳定结果指纹避免相同草稿重复创建。部分完成或中断结果不会伪装成已完成会话答案。

## 4. 受控工具

| 工具 | 实际行为 |
| --- | --- |
| search_knowledge | 检索当前可访问且生效的知识 |
| query_table | 完整来源快照上的筛选、排序、分组、计数、求和、均值、最小值、最大值及时间范围过滤 |
| compare_clauses | 提取并列条款原文，展示来源、适用范围和有效日期；不自动裁定制度效力 |
| create_report_draft | 根据已经完成且来源仍有效的工具结果，保存本地非正式草稿 |
| lookup_asset | 尚未配置并验收真实业务设备接口，调用会明确失败 |
| lookup_work_orders | 尚未配置并验收真实工单接口；已入库的工单快照可通过表格工具查询 |

表格计算每次最多读取 5,000 条来源记录，最多返回 200 条结果；最多 50 个展示字段、3 个分组字段、10 个聚合和 3 个排序字段。完整来源、筛选后的匹配行数和最终展示行数分别记录，展示不足不等同于计算来源缺失。计算保留实际来源行、过滤条件、缺失值数量和快照指纹。

数值运算采用 12 位小数定点算法，均值采用四舍五入且中点远离零；空白值从数值聚合中排除并单独计数。无法精确表示为 JavaScript 数字的结果以十进制字符串返回。没有任意 SQL、跨系统写入或自动工单提交。

工具输出进入生成上下文的总预算约为 18,000 字符；不能完整容纳时标记部分覆盖，要求进一步筛选。普通检索全表证据聚合还受 200 行、18,000 字符和最多 3 张表的预算约束，与确定性工具的 5,000 行计算范围不同。

## 5. 业务模板

维护模板和查看评测需要管理员权限。首建模板创建 v1；修改内容创建新版本。已发布版本不能原地修改，运行固定记录所使用的模板版本。当前仅注册 default 模型配置，不存在已配置好的多模型自动选型池。

| 方法与路径 | 用途 |
| --- | --- |
| GET /api/scenarios | 管理员查看全部版本，普通用户查看已发布版本 |
| POST /api/scenarios | 创建场景及 v1 |
| GET /api/scenarios/:id | 场景详情和版本 |
| POST /api/scenarios/:id/versions | 创建下一版本 |
| POST /api/scenarios/:id/rollback | 将通过评测的指定版本重新发布；请求包含 versionId |
| POST /api/scenario-versions/:id/evaluate | 异步执行该版本关联评测 |
| GET /api/scenario-versions/:id/evaluations | 当前版本的评测历史 |
| GET /api/scenario-evaluations/:id | 查询一次评测的进度与结果 |
| POST /api/scenario-versions/:id/publish | 发布经过完整评测的版本 |
| POST /api/scenario-versions/:id/disable | 停用版本 |

创建字段包含 name、scenario、goal、inputSchema、outputSchema、allowedTools、evaluationCases；可指定 modelProfile，但目前只能使用 { "profile": "default" }。

输入、输出 Schema 均为受限对象结构，最多 20 个字段，支持 string、number、integer、boolean、required 和有类型约束的 enum。不执行模板变量中的代码，不支持任意 JSON Schema 脚本或远程引用。输出有声明字段时，模型需返回 structuredOutput；服务端验证字段后才将其作为结构化输出返回。校验失败最多请求一次同证据格式修复，仍失败会明确降级。

evaluationCases 为内嵌题目数组，每版最多 30 题，字段为 question、baseId、expectedTerms、expectedDocumentId、mustRefuse。至少需要正常回答题和拒答题各一题。正向题要求真实 model 答案、必要文本及实际使用来源符合要求；拒答题要求依据不足且未使用引用。评测会使用当前配置的真实生成服务，可能产生费用。模板评测不会改变既有知识质量评测题或标准答案。

发布要求该版本关联评测全部完成、全部通过且其引用依赖仍有效。评测失败、身份失效、中断或只完成部分题目均不能发布。模板回退只影响后续运行。评测依赖资料变化后需要重新核验，不能把旧通过结果直接作为新版本的证据。

## 6. 模型配置与环境开关

本文件不包含密钥示例值。凭据应通过既有安全配置机制保存，不粘贴到日志、代码或共享文档。保存的模型设置优先于对应环境默认值；已保存 provider=disabled 时，单纯增加环境密钥不会自动启用生成模型。

| 配置项 | 实际用途与注意点 |
| --- | --- |
| AI_API_KEY / DEEPSEEK_API_KEY / OPENAI_API_KEY | 环境密钥读取优先级依次为左至右；已安全保存的模型凭据可覆盖环境默认值 |
| AI_BASE_URL | 兼容 Chat Completions 的生成服务基础地址 |
| AI_MODEL | 指定服务实际可用的模型名；应在部署时核验模型列表 |
| EMBEDDING_BASE_URL / EMBEDDING_MODEL / EMBEDDING_API_KEY | 独立向量服务配置；不能假定生成服务也支持 embeddings |
| LOCAL_EMBEDDINGS_ENABLED=false | 关闭本地 BGE 自动使用；默认在模型文件完整可用且没有独立外部向量配置时使用本地 BGE |
| MODEL_ALLOWED_HOSTS | 运维明确允许的内部 HTTPS 模型主机名，逗号分隔；不是任意网址或路径白名单 |
| SEMANTIC_MIN_SCORE | 向量候选最低相似度阈值；应通过固定评测再调整，不能将降低阈值当作质量提升 |

标准生成调用为基础地址后的 /chat/completions。DeepSeek 请求关闭其可选 thinking 模式；不得把文本接口误认为已具备视觉识别或音频转写能力。Ollama 配置允许本机 HTTP；其他生成服务默认要求 HTTPS，并拒绝未列入运维白名单的内部地址。

当前单次模型 timeoutMs 是保存设置，默认 60 秒，可限制在 5–120 秒；另受运行 90 秒总活动预算约束。没有 AI_TIMEOUT_MS、OTEL_EXPORTER_OTLP_ENDPOINT 等已接通的专属开关，设置这些名称不会自动启用相应能力。

本地 BGE 使用项目固定模型文件、512 维向量、CPU 推理及版本签名，运行时禁止下载模型文件；其部署准备与离线自检沿用 npm run model:prepare / npm run model:verify。模型缺失时诚实降级全文检索。本地推理不产生外部模型账单，但仍占用本机 CPU、内存和存储。

## 7. 用量、费用与调用链

GET /api/observability 仅供管理员查看，返回 metrics、modelUsage、recentRuns、errors、telemetry。GET /api/observability/traces/:traceId 返回链路、步骤及模型调用账本。HTTP 响应携带 X-Request-Id，运行记录包含 runId、traceId 和 attempt，可据此关联失败处理过程。

所有经过统一调用入口的连接测试、查询改写、生成、引用修复、工具规划、模板评测、向量处理均记录调用类别、开始时间、耗时、结果状态、尝试次数和供应商返回的用量。分类统计独立累加，不能把某分类误认为总用量。

只有响应同时提供有效输入、输出 token 数时，用量为 known。缺失用量、断流、取消、异常或重启中断记录为 unknown，token 字段保留 null，不能理解为免费或消耗为零。本地向量调用标记 billingApplicable=false；其供应商 token 用量通常不可用。

账本初始写入失败会阻止发起模型请求，返回 METERING_UNAVAILABLE。请求已经发生、但最终账本写入失败时，平台保留可识别的未结算状态并计数 meteringFinalizeFailures；恢复时标记中断和用量未知。诊断追踪写入失败另计 droppedTelemetry。这些指标需要运维处理，不能用估算值覆盖。

平台没有供应商账单对账、币种换算、价格表或自动费用估值；token 统计不能等同于最终扣费。一次用户请求可能触发改写、规划、生成及一次引用/结构修复，明确重试也可能重新产生调用。取消只能阻止后续处理，不能保证供应商对已接收请求不计费。

诊断 trace / span / modelCall 不记录密钥、问题全文、资料正文或工具结果正文，只保存必要元数据和错误类别。会话、运行步骤、工具结果和本地草稿仍包含业务内容，并存入同一 SQLite；它们不是匿名诊断日志，必须随业务权限、备份和数据保护策略管理。

当前追踪采用 W3C 长度格式的 trace/span 标识和 Node.js AsyncLocalStorage 本地关联。它没有接入 OpenTelemetry SDK、OTLP 导出器、Collector 或外部 APM，也不表示已实现跨系统分布式链路追踪。

保留策略实际为：详细 traceSpan 最多 7 天 / 20,000 条，trace 最多 30 天 / 10,000 条，modelCall 最多 30 天 / 20,000 条，达到任一上限可提前清理；正在执行的记录不按该规则删除。通常启动恢复及后台定时维护会执行清理。列表指标只覆盖当前保留数据，不能作为永久累计账本。

运行、事件、会话与草稿当前没有“30 天后自动删除”的承诺，随业务数据保留；telemetry.runRetentionDays 返回 null。需要长期费用归档、监管留存、明确删除周期或外部监控时，应另行配置并验收，不能依赖上述短期诊断统计。

## 8. 排错与验收

遇到 409 时先读取最新 conversationRevision 或 run.revision；同会话忙碌时等待、补充输入或取消已有运行。遇到依据变化，应重新检索；遇到表格结构待确认或来源冲突，应在知识治理中复核，不要绕过工具校验。遇到模型认证、额度、网络问题，应由管理员检查对应配置和调用错误类别，避免将密钥放进错误截图。

本模块专项使用真实本机 HTTP/SSE、临时 SQLite、离线 BGE 覆盖幂等、并发、重启、取消、权限撤销、表格计算、格式修复、引用、未知用量及评测发布。它验证实现路径，不替代目标部署上的真实模型效果或浏览器验收。

全量工程检查日志保存于 output/capability-upgrade/final-check.log；实际执行结果与计数以该日志及当次交付说明为准。npm run check 包含类型检查、生产构建、测试、离线模型自检和交付包安全核验，不自行调用正式付费生成服务。
