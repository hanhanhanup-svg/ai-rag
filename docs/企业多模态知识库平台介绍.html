ENTERPRISE MULTIMODAL KNOWLEDGE · X-RAG

企业多模态知识库
平台介绍

把分散在制度、表格、图纸说明、音视频中的企业资料，建成「找得到、管得住、用得开、有出处」的知识服务平台， 支撑业务查找、带依据问答与系统集成，辅助决策而不替代正式制度效力。

1. 总体定位与价值

企业知识往往散落在 PDF、Word、Excel、扫描件与音视频中。业务人员「问得到人、找不到依据」； 知识管理人员「有文档、难治理」；系统建设「有模型、缺证据」。本平台以多模态接入 + 证据核验 + 权限可控 + 场景化应用 为主线，形成可持续运营的企业知识底座。

找得着 · 场景与原文双路径 管得住 · 发布审核与版本 用得开 · 问答 / 图谱 / 标准接口

对业务人员

按任务、对象、问题快速定位有效资料；问答结果带回原文引用，减少「凭印象答复」。

对知识管理员

统一接入、解析、属性标注、重复冲突核验、知识卡片与需求池，形成可运营的知识生产流水线。

对平台与 IT

服务端鉴权、审计留痕、模型与解析服务可配置；标准知识接口可被业务系统安全调用。

一句话口径： 将企业多模态资料纳入「授权可控、原文可溯、发布可审、接口可集成」的知识闭环，支撑业务场景查找与带依据智能问答，并以需求池、卡片、评测与审计持续治理质量。

3.2 知识生产与应用功能分层

生产侧（让知识「进得来、标得准」）

· 多模态解析：文本 / 表格 / OCR / 音视频抽帧
· 属性标注：模板识别草稿 + 人工确认生效
· 知识卡片：结构化口径，发布须关联原文依据
· 图谱对象：关系候选确认，避免未核验路径进入问答

应用侧（让知识「找得到、答得住」）

· 综合查找：意图分流至场景 / 文档 / 图谱
· 智能问答：模型归纳与原文摘录区分，强制引用
· 业务场景：评测通过后发布，工具白名单可控
· 标准接口：业务系统按绑定范围安全调用

  • 属性标注：在解析任务页完成文档 / 片段级属性建议与确认，服务检索过滤与问答条件。
  • 知识卡片：概念解释、规则说明、操作指引、常见问答四类模板；草稿不作为标准口径，冲突并排保留。
  • 完整性补全：对问答运行解析应答要点清单；智能补全仅给结构 / 澄清建议，知识补全必须带证据。
  • 知识需求池：缺口自动归集为「待确认」工单，支持分派、复测、关闭；禁止用重复灌库强行关闭检索类问题。

前端

存储与运行

单节点 SQLite（WAL）+ 原件目录；模型密钥服务端密封；本地运行追踪与用量账本，便于试点阶段运维。

4.3 问答与检索技术路径

环节做法领导关注点
检索 BM25 + 可选向量，RRF 融合；可叠加已确认图谱路径 先保证「找得到原文」，再谈生成
生成 可配置兼容 Chat Completions 或本地 Ollama 模型可替换，不绑死单一厂商
引用 答复区分归纳 / 摘录 / 依据不足；回链页码或证据块 可核验，降低幻觉风险
补全 smart 仅结构澄清；knowledge 必须有证据；否则进需求池 不凭常识编造企业时限、审批权限等

5. 核心业务闭环

平台不是「一次上传、永久可用」，而是持续运营的知识供应链。

flowchart TD
  S1["① 接入\n上传 / 同步"] --> S2["② 加工\n解析 · 索引 · 属性"]
  S2 --> S3["③ 核验\n证据 · 图谱 · 重复冲突"]
  S3 --> S4["④ 发布\n审核 · 版本 · 生效失效"]
  S4 --> S5["⑤ 应用\n查找 · 问答 · 场景 · 接口"]
  S5 --> S6["⑥ 回流\n反馈 · 完整性 · 需求池"]
  S6 --> S7["⑦ 改进\n补卡 · 修订 · 评测回归"]
  S7 --> S4
图 6　知识运营七步闭环

发布状态机

资料：排队 → 解析 → 待审 → 已发布；卡片：草稿 → 审核 → 有证据后发布；图谱关系需人工确认。

质量回流

用户反馈可沉淀为可学习结论；问答缺口进入需求池；评测题库检验场景版本是否可发布。

对外赋能

标准知识接口绑定库 / 场景 / 任务范围，密钥可轮换；调用方无法扩大授权边界。

6. 安全、治理与建设边界

安全与权限

· 知识库可见范围：企业 / 部门 / 指定成员
· 文档保密级别：内部 / 受限
· 列表、原件、搜索、问答、接口均服务端鉴权
· 写操作 Origin 校验；会话 HttpOnly
· 关键动作进入操作审计

治理原则（明确不做）

· 属性标签不替代文档 ACL
· 不自动把多来源冲突揉成「唯一标准答案」
· 不凭模型常识填写审批权限、时限、金额等企业事实
· 知识卡片不替代正式文件法律效力
· 当前定位：部门试点可部署，非已验收的高可用集群

管理提示： 平台产出的答复与卡片是「可追溯的业务辅助口径」。涉及对外承诺、审批结论、安全操作时，仍应以现行有效正式文件与制度流程为准。

7. 建设成效与推进建议

7.1 已形成的能力资产

  • 覆盖接入、资产、应用、治理、运营、管理的完整功能骨架。
  • 多模态处理与混合检索底座，支持「无向量也可用、有向量更准」。
  • 引用式问答 + 场景评测发布，降低不可核验答复进入生产的风险。
  • 属性 / 卡片 / 完整性 / 需求池打通「发现缺口 → 补知识 → 再验证」闭环。
  • 标准知识接口便于与既有业务系统集成，避免把大模型裸接进业务。
